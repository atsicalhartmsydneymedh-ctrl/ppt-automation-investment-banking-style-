```yaml
id: R3-L01
inherits: ../../ppt_design_mechanism_library/global_defaults.yaml
name: center_anchor_multi_layer_radial_atlas
industry_specific: false
relation: one_anchor -> multiple_groups -> concrete_items -> optional_downstream_outcomes

match_when:
  - 一个共同主体统领3–8个方向、领域、能力或产品系列
  - 每个方向包含至少2个可识别的具体对象
  - 具体对象需要通过空间位置体现所属方向
  - 可选存在第二分类维度或下游应用层
  - 页面表达覆盖、生态、组合或连接，不表达时间先后

reject_when:
  - 没有真实共同主体
  - 对象无法稳定归类，只能随机环绕
  - 主要关系是流程、时间轴、因果链或精确数值比较
  - 一级类别少于3个或总证据少于10项

slots:
  required:
    anchor: 公司/平台/品牌/核心技术/核心设备/共同能力
    primary_groups: 3–8个一级类别
    evidence_items: 10–45个产品/能力/案例/客户/应用/数字
  optional:
    secondary_layers: 0–4个第二分类维度
    outer_outcomes: 下游应用/终端产品/客户结果/使用场景
  bindings:
    - evidence_item必须绑定primary_group
    - 使用secondary_layers时，evidence_item必须同时绑定secondary_layer
    - outer_outcome必须能回指至少一个evidence_item或primary_group

variants:
  V1:
    relation: anchor -> groups -> evidence
    layout: 中心锚点 + 周向分区 + 分区内证据
  V2:
    relation: anchor -> dimension_A × dimension_B -> intersection_evidence
    layout: 周向扇区编码A，同心层编码B，证据落在交叉区域
  V3:
    relation: anchor -> products_or_capabilities -> downstream_outcomes
    layout: 内层类别，中层具体对象，外围下游应用或成果
  V4:
    relation: anchor -> groups_with_unequal_evidence_volume
    layout: 非等角分区，按真实证据量调整但最大/最小不超过2.2倍

layout_dna:
  - 全页只有一个中心锚点和一个连续圆形/椭圆形信息场
  - 主体占页面宽82%–92%、高66%–75%
  - 中心锚点占主体宽18%–26%
  - 一级类别用周向分区；第二维用同心层；下游结果放外围
  - 空间位置编码归属，不能仅依靠文字说明
  - 使用底色、细分隔线和距离建立弱边界，不做卡片墙
  - 证据数量可以不均衡，不强制各区组件完全对称

content_limits:
  title: 单行，14–24个汉字
  group_label: 2–8个汉字
  evidence_items_per_group: 2–8
  total_evidence_items: 10–45

assets:
  structure: PPT原生形状
  evidence: 透明产品图/应用图/真实场景/官方Logo/关键数字
  policy:
    - 项目图片不进入通用素材库

    - 图片承担证据作用，不用同质图标随机填充

style:
  cjk_font: KaiTi
  latin_numeric_font: Arial
  boundary: weak
  avoid: [卡片墙, 按钮感, 随机环绕, 无意义渐变, 3D, 发光]

qa_specific:
  - 删除行业名词后关系仍成立
  - 每个证据均有可追溯归属
  - 中心主体与全部一级类别真实相关
  - 径向距离、扇区面积和图片大小不制造虚假含义
  - 没有退化为平均网格或多个独立面板

generic_relation_example:
  - 共同主体 -> 多个方向 -> 具体产品/设备/方案 -> 下游应用/终端产品/结果
```

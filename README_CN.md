# Report-to-Consulting-Slides

一套“效果图优先”的高密度咨询 PPT 工作流：先把报告内容、证据关系和页面构图设计正确，再生成效果图，并将效果图交接为可编辑 PowerPoint。

这不是一组“咨询风、科技感、高级感”的提示词，也不是把长文直接塞进模板。工作流的核心路径是：

`原始材料 → 证据地图 → 故事线与分页 → 单页论证 → 证据图形 → 构图决策 → 逐页效果图 → 图片素材拆解 → PPT 重建包 → 可编辑 PPT`

## 推荐使用方式

本工作流首先交付经过逐页验收的 PPT 效果图。生成可编辑 PPT 时，推荐搭配 **GPT for PPT / ChatGPT for PowerPoint** 使用：效果图负责锁定视觉目标，重建 Prompt、固定字号和素材包负责降低字体漂移、图标缺失和页面结构走样。

也可以把效果图、字号规范和素材包交给其他能够生成或编辑 PowerPoint 的 AI，让它按照效果图重建可编辑 PPT。需要注意：单独提供效果图通常不足以稳定还原页面，必须同时说明哪些元素应使用原生 PPT 对象，哪些元素必须作为图片插入。

## 当前主程序入口

主程序默认采用“阶段状态机”，不会再按字符切分后批量出图。每次运行只推进一个明确阶段，所有中间文件和批准状态都保存在同一个输出目录，可以中断后继续。

```powershell
# 准备：解析报告、提取参考风格、生成内容地图和候选整套合同
scripts\run_latest_report.ps1 -Stage prepare -CoreReference "input\核心参考-模板.pptx" -Output "output\项目名"

# 审核 deck_contract.json 后，锁定分页和来源覆盖
scripts\run_latest_report.ps1 -Stage approve-deck -Output "output\项目名"

# 每次只准备、批准和生成一页
scripts\run_latest_report.ps1 -Stage prepare-page -Page 1 -Output "output\项目名"
scripts\run_latest_report.ps1 -Stage approve-page -Page 1 -Output "output\项目名"
scripts\run_latest_report.ps1 -Stage generate -Page 1 -Output "output\项目名"
scripts\run_latest_report.ps1 -Stage approve-image -Page 1 -Output "output\项目名"

# 查看当前进度和下一步
scripts\run_latest_report.ps1 -Stage status -Output "output\项目名"
```

`prepare-page` 会按页面语义关系从68张机器执行卡中选择构图机制，并把机制的空间语法与专项QA写入页面计划。中文固定使用楷体，英文、数字和标点固定使用 Arial。旧版批量流程仅通过 `-Legacy` 显式启用。

## 完整工作流

### 1. 解析原始材料

读取 DOCX、PDF、TXT、XLSX 等资料，提取章节、事实、数据、案例、结论、风险和来源位置。

### 2. 建立参考风格契约

从用户指定的核心参考 PPT 中动态提取画布比例、实际色板角色、字体层级、标题锚点、内容边界、页脚规范、线条处理、信息密度和留白节奏，并生成项目级 `hard_constraints`。只要指定了核心参考 PPT，规划器和效果图提示词就不得混入默认主题色；参考文件控制视觉气质，但不直接限制每页构图。

### 3. 建立全报告内容地图

把重要内容映射到可追溯的来源区块，明确哪些内容被采用、合并或有理由地省略，避免遗漏与重复。

项目可以在配置中提供轻量 `project_brief`，明确PPT类型、独立可读性、观众、目的、希望形成的决定和核心结论。原始解析结果始终保留为 `parsed_blocks_raw.json`；若本次试运行配置了待核实或口径冲突标记，程序只从PPT生成副本中删除命中的句子、列表项或表格行，并把明细写入 `content_map/narrative_exclusions.json`，不修改原报告。

### 4. 设计故事线与分页

生产模式把全文转换成 `content_map/narrative_source_payload.json`：只保留内容与不可反推顺序的匿名来源标识，不向分页AI提供Heading类型、章节级别、页码、原始位置或连续的来源编号。分页器通过 DeepSeek Chat Completions 接口调用 DeepSeek；模型必须通读全部语义记录，比较候选叙事线，允许跨越原章节重新组合证据，并用 JSON Output 返回完整分页合同。程序再按完整 JSON Schema 做确定性校验，不通过时只允许一次定向修复。字符数、标题格式和原文顺序均不参与分页；如果AI不可用或合同校验失败，流程停在 `narrative_ai_required`，不得回退到规则分页。

首次使用时把 `.env.example` 复制为 `.env`，在本机填写 `DEEPSEEK_API_KEY`；默认请求地址为 `https://api.deepseek.com/chat/completions`，默认分页模型为 `deepseek-v4-pro`，也可在配置中调整模型。密钥不要写入报告、提示词或提交到仓库。Paratera/Kimi 配置仅为自定义路由保留，不再用于默认分页。

分页通过后会额外生成 `content_map/restructure_report.json` 与 `.txt`。若新页面组合了原报告不同位置的内容、改变了原有顺序或进行了明显拆分合并，报告会明确标记“本次分页未沿用原报告章节结构，已根据全文论证关系进行较大重组”，并列出逐页来源映射、遗漏与复用。

同时生成 `content_map/storyline_readthrough.txt`，把全部观点句标题串联为一条连续文本，在批准分页前检查页面之间是否跳跃、重复或缺少收束。

### 5. 编写单页论证

在设计版式之前，先写清楚页面要证明什么、使用什么数据或案例、正文如何解释证据，以及最终的 SO WHAT。

### 6. 设计证据图形

根据内容关系选择时间轴、矩阵、价值链、漏斗、分层结构、路径图、定量图表或其他语义图形。图形必须承担论证功能，不能只作为装饰。

### 7. 完成构图决策

按照以下链路确定页面视觉结构：

`沟通目标 → 信息密度 → 设计强度 → 视觉策略 → 页面原型 → 空间叙事 → 素材策略`

这一步用于避免连续页面重复使用卡片宫格，并判断页面是否需要主视觉、地图、复杂图形或高密度证据区。

选择页面原型前，先为每页生成 `page_structures/page_XX.json`，同时输出供AI生成/复核该合同的 `page_XX_prompt.txt`。结构文件只记录内容组数量、组间关系、组内关系、顺序、映射、容量和证据形态，不记录行业、品牌、色调或固定区域比例。匹配器使用这份结构合同与执行卡顶部的 `mechanism-card-v3` 合同做硬门槛匹配，并将结果写入 `mechanism_matches/page_XX.json`；区域宽度和高度在命中后根据内容量自适应。不得从 `suggested_visual_type` 反推关系，也不得按行业、品牌、来源页关键词或表面外观匹配机制。

68张执行卡均使用v3合同：`match_signature`负责检索，`layout_contract`负责版式骨架，`encoding_contract`先执行卡片优先表达、再回退到全局数字编码规则。旧YAML块只保留为来源注释，不参与机器匹配。可运行 `scripts/audit_mechanism_library_v3.py` 审计全库。

### 8. 逐页生成并验收效果图

一次只处理一页。检查内容覆盖、数据准确、图文对应、层级、密度、参考风格和画布比例；当前页通过后再继续下一页。`approve-image` 会生成 `approvals/page_XX_visual_qa.json`，硬检查画布比例、核心参考色板偏离、过度空白，以及显式左右/上下分组是否都有可见内容；标题文字准确性、楷体+Arial、页脚规范和机制关系仍由该人工批准动作逐项确认。

页面设计稿必须遵循 [`docs/design_draft_contract.md`](docs/design_draft_contract.md) 的固定结构。设计稿是包含语义关系、主视觉、证据映射、视觉编码、层级和空间坐标的生产合同，不能退化为配色、字号和区域比例摘要。进入效果图生成前，必须使用工作区 Python 运行 `src/design_draft_validator.py <draft>` 并通过校验。

如果第一版设计稿或效果图出现信息密度偏低，只能在已确认设计稿上提交**排版优化补丁**，不能重新生成或覆盖设计稿的核心结构。结论、语义关系、主视觉、证据映射、视觉编码、阅读层级和反模板约束默认锁定；只允许优化区域占比、对齐、留白、标签位置、字号层级、局部强调和冗余容器。典型触发条件包括：大面积无意义留白、标题或卡片尺寸过大、页面只有少量短句、原文中的数据/案例/对比未被使用、图表只有装饰作用，或明显低于核心参考 PPT 的信息密度。

可直接使用以下反馈：

> 第一版的信息密度偏低。请以已批准设计稿为母版，只提交排版优化补丁，不得重写设计稿。锁定页面结论、语义关系、唯一主视觉、证据映射、图表视觉编码、主次层级和反模板约束；仅优化区域比例、对齐、留白、标签位置、字号层级、注释贴近度和冗余容器。完成后输出包含全部固定章节的合并设计稿，并使用原设计稿作为 `--base` 通过校验，再生成高密度效果图。

“高密度”指单位页面承载更多有效论证和证据，不等于单纯缩小字体或增加更多方框，也不是一种可以覆盖原设计合同的新设计模式。密度现在按页面证据负载相对于整套演示的分布计算，不再按字符阈值统一打满；区域尺寸在机制匹配后依据项目数量、标签长度和证据优先级自适应，不使用固定百分比。排版优化后的完整设计稿不得因删减设计细节而明显短于母版；可使用工作区 Python 运行 `src/design_draft_validator.py <merged_draft> --base <approved_base_draft>`，检查设计核心是否被误改。

### 9. 识别图标与图片元素

效果图确认后，对页面中的所有视觉元素进行拆解，分为两类：

- **原生 PPT 对象**：标题、正文、色块、边框、分隔线、箭头、表格、简单图表和基础几何图形；
- **外部图片素材**：图标、地图、照片、Logo、插画、纹理、复杂装饰图形，以及 PowerPoint 或 GPT for PPT 无法稳定自主生成的元素。

素材处理规则：

1. 建立逐页素材清单，记录素材编号、文件名、含义、使用位置、推荐尺寸、插入方式和来源；
2. 公司 Logo 优先使用官方网站或官方品牌资源，不使用 AI 生成的近似 Logo；
3. 地图、通用图标和公开素材优先选择授权明确的来源；找不到合适素材时再生成通用插画或图标；
4. 默认提供透明背景 PNG，并保留 SVG 作为备用；
5. 生成图标总览图，方便人工核对素材是否完整、风格是否一致；
6. 保存来源与授权说明，避免公开发布或商业使用时产生版权风险；
7. 在重建 Prompt 中同时写入绝对路径和可移植相对路径；
8. 如果 AI 无法读取必需素材，应停止并要求用户重新上传，禁止用 emoji、Wingdings、Unicode 符号或临时几何图形代替。

### 10. 生成 PPT 重建包

每页重建包通常包括：

- 已确认的页面效果图；
- GPT for PPT 重建 Prompt；
- 页面尺寸与主要区域坐标；
- 标题、正文、标签、来源和页码的固定字号；
- 原生 PPT 对象与外部图片素材的边界说明；
- PNG、SVG、素材清单、图标总览和授权说明；
- 可独立传输的 ZIP 压缩包。

默认字体规范：中文使用楷体（KaiTi），英文、数字和标点使用 Arial。禁止自动缩小字体；出现溢出时优先调整文本、文本框和间距。

### 11. 重建可编辑 PPT 并进行 QA

使用 GPT for PPT 或其他 PPT 生产工具按照效果图重建页面。最终检查字号、字体、素材完整性、图片比例、对象可编辑性、数据准确性、文字溢出、元素重叠和整体还原度。

## 两种交付模式

### 模式 A：效果图交付

适用于需要先确认视觉方向、制作汇报样稿或交给专业设计师继续加工的场景。

### 模式 B：可编辑 PPT 交付

推荐采用：

`效果图 + 固定字号 + 图片素材包 + 重建 Prompt + GPT for PPT`

相比只给 AI 一张效果图，这种方式能够显著减少字号错误、图标缺失、素材误替换和页面结构漂移。

## 项目边界

- 工作流优先保证内容论证、证据完整性和视觉设计质量，不承诺用一个提示词一次生成最终 PPT；
- 效果图中的文字和数字不能替代原始材料中的真实证据；
- 高复杂度页面仍可能需要少量人工微调；
- 可编辑不等于所有视觉元素都必须原生绘制。复杂视觉保留为图片、核心信息保持可编辑，通常能取得更好的保真度与生产效率。

## 当前输出结构

```text
output/<run_id>/
├─ content_map/             # 全报告内容地图与故事线
├─ content_arrangements/    # 单页内容方案
├─ evidence_specs/          # 证据图形规范
├─ design_drafts/           # 页面设计稿
├─ slide_plans/             # 含构图机制选择的机器页面计划
├─ slide_images/            # 已验收效果图
├─ approvals/               # 整套、单页和效果图批准记录
├─ ppt_rebuild_packages/    # 字号、素材和 PPT 重建包
└─ workflow_state.json      # 可中断续跑的当前状态与下一步
```

## 一句话介绍

> 先把报告变成有证据链、有结论、有构图的页面效果图，再通过固定字号、图片素材包和重建 Prompt，将效果图可靠地还原为可编辑 PPT。
